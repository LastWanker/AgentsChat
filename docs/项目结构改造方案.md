# AgentsChat 项目结构改造方案（LangGraph-Ready 统筹版）

## 1. 改造目标（双目标合并）

本方案同时服务两个任务：

1. 理顺项目结构（可维护、可测试、可扩展）。
2. 为 LangGraph 引入预留稳定接口（可渐进替换编排层）。

核心原则：

- 先“解耦”再“替换”：先把业务能力从运行循环中拆出，再接 LangGraph。
- 业务语义不变：`IntentionDraft -> FinalIntention -> Event` 链路保持。
- 单一事实源：业务事实仍以 `EventStore` 为准，工作流状态用于编排。
- 双引擎共存：在一段时间内同时保留 `LegacyLoopEngine` 与 `LangGraphEngine`。

## 3. 类与函数迁移（按可替换性分组）

## 3.1 业务能力（先稳定，不绑定 LangGraph）

- `agents/proposer.py::IntentionProposer` -> `application/proposer/intention_proposer.py`
- `events/intention_finalizer.py::IntentionFinalizer` -> `application/finalizer/intention_finalizer.py`
- `agents/interpreter.py::IntentInterpreter` -> `application/interpreter/intent_interpreter.py`
- `platform/router.py::Router` -> `application/router/intention_router.py`
- `events/reference_resolver.py::ReferenceResolver` -> `application/finalizer/reference_resolver.py`

## 3.2 编排能力（为双引擎准备）

- `runtime/loop.py::RuntimeLoop` -> `workflow/legacy_loop_engine.py`
- `_should_finalize` -> `workflow/routes/should_finalize.py`
- “选人/提案/终稿/路由”流程步 -> `workflow/nodes/*`
- 新增 `workflow/engine.py::WorkflowEngine`（统一接口）

建议接口：

- `run(max_steps: int | None = None) -> None`
- `resume(thread_id: str) -> None`
- `step(input: dict | None = None) -> dict`

## 3.3 基础设施（可复用）

- `events/store.py`、`events/query.py` 保持为 `infrastructure/persistence/*`
- `events/session_memory.py` 先不大改语义，只做文件拆分
- `platform/world.py` 改名到 `interfaces/event_bus/world_bus.py`

## 4. 分阶段实施（结构与 LangGraph 一体化）

## Phase 0：先可运行（1-2 天）

1. 引入 `src/agents_chat` 包结构。
2. 统一入口 `python -m agents_chat.app.cli`。
3. 测试不再依赖手工 `PYTHONPATH`。

交付标准：旧流程仍可跑通。

## Phase 1：先解耦编排（2-4 天）

1. 引入 `workflow/engine.py` 抽象。
2. 现有 `RuntimeLoop` 迁到 `legacy_loop_engine.py`。
3. 将流程函数拆到 `workflow/nodes`、`workflow/routes`。

交付标准：行为不变，但已具备“可替换引擎”结构。

## Phase 2：基础设施清理（2-4 天）

1. `platform -> interfaces` 改名，去掉与标准库同名风险。
2. `runtime/bootstrap.py` 拆为 config/builder/runtime。
3. `test4*.py` 迁移到 `examples/`；`tests` 按 unit/integration/e2e 重排。

交付标准：目录语义稳定，改造成本下降。

## Phase 3：LangGraph 试点接入（3-5 天）

1. 新增 `workflow/langgraph_engine.py`。
2. 先接一条最小链路：`select -> propose -> finalize -> route`。
3. `session_id -> thread_id` 映射；checkpoint 仅存流程状态。
4. 增加配置开关：`WORKFLOW_ENGINE=legacy|langgraph`。

交付标准：同输入下，事件落盘语义与 legacy 基本一致。

## Phase 4：切换与收敛（2-3 天）

1. 对齐回归测试（事件数量、类型、引用结构）。
2. 默认引擎切换到 LangGraph，legacy 保留一个版本周期。
3. 完成迁移文档与回滚策略。

## 5. 统筹依赖关系（很关键）

- LangGraph 引入依赖 Phase 1（编排抽象）先完成。
- 在 Phase 1 完成前，不建议直接把 `runtime/loop.py` 改写成 LangGraph。
- `SessionMemory` 不作为首批迁移目标，避免并发+持久化叠加风险。

## 6. 验收清单

1. 目录可解释：看到路径知道职责。
2. 存在双引擎：`legacy` 与 `langgraph` 可切换。
3. 业务链路保持：Draft/Final/Event 结构不破坏。
4. `EventStore` 仍是事实源。
5. 关键测试覆盖编排等价性与恢复能力。

## 7. 当前收口顺序（已执行）
