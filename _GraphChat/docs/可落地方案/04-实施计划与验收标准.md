# 04 实施计划与验收标准

## 1. 实施节奏（可运行增量）

## Phase 0：基础脚手架（2-3 天）

交付：

- 分层目录与依赖规则落地
- `Action Contract / Event Contract / Scope Contract` schema
- 最小 `WorldGraph` 空转主循环

验收：

- 图可编译、可运行、可持久化 checkpoint
- 非法动作被拒绝

## Phase 1：单 Agent 主流程（4-6 天）

交付：

- `AgentGraph`：`listening -> plan_action -> policy_gate -> emit_event`
- `SilentLoopSubgraph` 首版

验收：

- Agent 可在静默与行动间切换
- 重启后能从 checkpoint 恢复

## Phase 2：世界并发调度（4-6 天）

交付：

- `WorldGraph` 并发分发（`Send`）
- 主群/小群/私聊 scope 路由

验收：

- 多 Agent 并发推进
- 可见性符合 scope 规则

## Phase 3：检索与引用（5-8 天）

交付：

- `RetrievalSubgraph`
- `citation_guard_node`
- `focus + support` 引用结构

验收：

- `required_focus` 场景可追溯
- 无证据场景自动改道

## Phase 4：任务板与治理动作（4-6 天）

交付：

- `BoardSubgraph`
- `vote_decision` / `dissolve_group` / `maintain_board`

验收：

- 任务板可增删改查与回放
- 治理动作具备审计事件链

## Phase 5：HITL + 流式（3-5 天）

交付：

- `interrupt/resume` 全链路
- token 流 + 节点更新流
- 输入分片桥接

验收：

- Boss 可中途介入并恢复
- 长会话运行稳定，无重复副作用

## 2. 测试矩阵（必须自动化）

- `state_machine`: 转移合法性、死锁检测
- `scope_visibility`: world/group/dm 可见性正确
- `citation_guard`: 条件化引用校验
- `interrupt_resume`: 中断恢复幂等
- `board_consistency`: board 与事件一致
- `replay_consistency`: 事件重放一致

## 3. 发布闸门

每个 Phase 的发布必须满足：

- 单元测试与集成测试通过
- 关键事件有可追溯 trace
- 性能基线达标（P95 延迟、错误率、恢复成功率）

## 4. 可扩展性硬指标

- 新动作接入不改主图结构，只加注册项与执行节点/子图
- 旧节点升级为子图时，上游接口不变
- 新存储实现替换不改 domain/application 层代码
