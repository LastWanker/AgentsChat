# 01 架构总览与分层边界

## 1. 架构目标

本项目采用双层图：

- `WorldGraph`：世界调度、可见性路由、并发分发、事件提交。
- `AgentGraph`：每个 Agent 的独立状态机（倾听、决策、检索、治理、输出）。

设计目标：

- 支持主群 + 小群 + 私聊三层 scope。
- 每个 Agent 独立线程、独立 checkpoint。
- 每个行为都事件化、可回放、可审计。
- 每个状态都可演进为子图，避免主图肥大。

## 2. 分层与依赖规则（低耦合）

## 2.1 分层定义

- `domain`：纯数据与规则（事件模型、动作契约、引用契约、board 模型）。
- `application`：图编排与用例（graph builder、nodes、routes、policies）。
- `infrastructure`：外部实现（LLM、向量库、SQLite/Postgres、文件系统、网络工具）。
- `interfaces`：CLI/API/UI、输入输出适配器、观测与管理接口。

## 2.2 依赖方向

- `interfaces -> application -> domain`
- `application -> infrastructure`（通过端口/协议接口）
- `domain` 不依赖任何框架实现

禁止：

- `domain` import `langgraph/langchain`
- `application` 直接读写 UI 层对象
- `interfaces` 绕过 `application` 直接操作持久化

## 3. 核心边界契约

## 3.1 Action Contract（可扩展）

基础动作：

- `speak`
- `ask_agent`
- `listen_only`
- `search_web`
- `request_file`
- `share_file`
- `create_group`
- `join_group`
- `assign_task`
- `vote_decision`
- `dissolve_group`
- `maintain_board`
- `escalate_to_boss`

动作注册字段（最小）：

- `action_id`
- `version`
- `scope_limit`
- `approval_policy`
- `citation_policy` (`none|optional|required_focus`)
- `enabled`

## 3.2 Event Contract（事实层）

最小结构：

```json
{
  "event_id": "e_xxx",
  "session_id": "s_xxx",
  "world_scope": "group:main",
  "actor_id": "agent_3",
  "action_id": "speak",
  "action_version": "1.0.0",
  "payload": {},
  "references": [],
  "focus_reference": null,
  "created_at": "2026-03-10T00:00:00Z",
  "trace": {"node": "emit_event", "thread_id": "s_xxx:agent:3"}
}
```

## 3.3 Scope Contract（可见性）

- `group:main`：主群默认全员可见。
- `group:<group_id>`：小群可见。
- `dm:<a>:<b>`：双边可见。

规则：事件始终写入全量事实库，可见性只影响消费方，不影响事实持久化。

## 5. 与 LangGraph/LangChain 对齐原则

- 图编排只用 LangGraph 官方图 API（`StateGraph`、`add_node`、`add_edge`、`add_conditional_edges`、`compile`）。
- 中断恢复使用官方 `interrupt(...)` + `Command(resume=...)`。
- 并发分发使用官方 `Send(...)`。
- 节点内模型调用使用 LangChain 模型抽象与工具抽象，不在图层直接拼 SDK。
