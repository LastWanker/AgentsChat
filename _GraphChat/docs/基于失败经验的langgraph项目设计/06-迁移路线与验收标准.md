# 06 迁移路线与验收标准

## 1. 迁移策略总原则

- 不在旧循环里继续打补丁。
- 用“增量替换”而不是“一次性推翻”。
- 每阶段都可运行、可回滚、可验收。

## 2. 分阶段实施

## Phase 0：契约先行（3-5 天）

目标：

- 固定 `Action Contract` 与 `Event Contract`。
- 固定 `citation_policy`（`none|optional|required_focus`）和条件化校验规则。

交付：

- 结构化 schema 文件（含动作注册表版本字段）。
- 事件写入与校验测试用例。

验收：

- 非白名单动作全部拒绝。
- `required_focus` 行为无焦点引用时被拦截，`optional` 行为允许无引用。

## Phase 1：AgentGraph 本体化（5-8 天）

目标：

- 从“legacy.step 包壳”升级为真实节点图。
- 先完成单 Agent 图：`listen -> plan -> retrieve -> guard -> emit`。

交付：

- 新 `agent_graph.py`。
- 节点级日志与状态转移事件。

验收：

- 单 Agent 在 idle/listen/plan 之间正确循环。
- 重启后可从 checkpoint 继续。

## Phase 2：WorldGraph + 多 Agent 并发（5-8 天）

目标：

- 增加世界图调度。
- 支持 `Send` 并发分发到多个 Agent。
- 固定主群/小群/私聊三层 scope 路由。

交付：

- `world_graph.py`
- `group_registry` 与 scope 路由器。

验收：

- A/B/C 可处于不同状态并并发推进。
- scope 过滤正确，事件可见性符合预期。

## Phase 3：HITL 与 Boss 介入（3-5 天）

目标：

- 接入 `interrupt/resume` 协议。
- Boss 审批流程完整事件化。

交付：

- 中断节点与审批队列。
- 恢复命令桥接。

验收：

- 风险动作触发暂停。
- Boss 决策后恢复线程且无重复副作用。

## Phase 4：RAG 升级与引用价值排序（5-10 天）

目标：

- 多通道召回（群内/对人索取/联网/文件）。
- 从“唯一主引用”升级为“焦点引用 + 辅助引用”。
- 评分器采用“可计算特征优先，LLM 只做解释”。

交付：

- 召回融合评分器。
- 引用守卫节点与可解释输出。

验收：

- `required_focus` 行为可追溯焦点引用。
- 焦点/辅助引用都来自候选集且分数可解释。
- LLM 分数失真不会直接导致越界输出。

## Phase 4.5：任务板/记录板一等化（3-5 天）

目标：

- 把任务板从“上下文文本”升级为“图节点 + 持久化实体”。

交付：

- `board_read_node` / `board_update_node` / `board_gc_node`。
- `board_items` 表与对应事件。

验收：

- 任务项可增删改、可审计、可回放。
- Agent 重启后可恢复任务板状态。

## Phase 5：流式输入输出与可观测面板（3-6 天）

目标：

- token 流 + 节点更新流双通道。
- 用户输入分片事件化。

交付：

- 输入适配器。
- 运行态面板（状态、审批、引用溯源）。

验收：

- 输入分片不造成图抖动。
- 实时看到 agent 状态变化和输出流。

## 3. 核心测试矩阵

- `state_machine`: 状态转移合法性与死锁检测。
- `citation_guard`: 条件缺引用/越界引用/错误引用角色。
- `interrupt_resume`: 恢复后幂等。
- `scope_visibility`: world/group/dm 可见性。
- `board_consistency`: 任务板增删改与事件流一致。
- `replay`: 基于事件日志重放一致性。

## 4. 成功判据（你最关心的体验指标）

- Agent 不再“角色漂移”，可稳定保持身份与职责。
- “空闲-倾听-行动”切换自然，且可被随时打断。
- 每次行为都可在世界事件流中看到，并可追溯引用依据。
- Boss 能中途介入，不需要重启会话。
- 系统不靠提示词玄学，而靠图状态和契约运行。
