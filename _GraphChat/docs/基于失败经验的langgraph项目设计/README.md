# 基于失败经验的 LangGraph 项目设计（重开版）

> 目标：把当前“能跑但边界混乱”的多 Agent 实验，重构为“图驱动、事件可追溯、状态可控、可暂停干预、可本地持久化”的标准 LangGraph 架构。

## 1. 这份设计解决什么

本设计直接针对你提出的核心诉求：

- 有清晰行为边界（不是只靠 Prompt 约束）。
- 动作集合可扩展（支持投票、解散群、任务板维护等新增动作）。
- 有图（World + Agent 双层图）且每个 Agent 状态独立。
- 事件是唯一事实源，世界 scope（群内）可见。
- 有 RAG 召回，支持“条件化引用约束”（并非所有行为都强制主引用）。
- 能暂停，让 Boss 介入并恢复执行。
- 支持流式输入/输出，并把行为过程完整事件化。
- 上下文与记忆本地保存，可恢复、可审计。

## 2. 为什么要重开设计

你当前仓库已经很好地积累了“失败经验”：  
`LangGraph` 目前主要是外层包裹 legacy step，而不是业务状态机本体；记忆检索有雏形但约束还弱；每个 Agent 的独立线程/状态模型还未成型。  
所以这次不再做补丁式修修补补，而是先统一“图模型 + 事件契约 + 状态边界”。

## 4. 关键设计原则（固定不变）

- 事件优先：所有行为先写事件，再做广播与推理。
- 强状态机：动作从状态机路由，不从自然语言猜测。
- 独立线程：每个 Agent 使用独立 `thread_id` 与 checkpoint。
- 显式中断：所有 Boss 介入必须走 `interrupt/resume` 或等价事件协议。
- 先可控再智能：先约束动作空间和验证，再增加模型自由度。
