# 01 总体架构与行为边界

## 1. 经典 LangGraph 思路在本项目的落点

不是“一个大 while loop + LLM 自由发挥”，而是：

- `WorldGraph` 负责世界事件流与调度。
- `AgentGraph` 负责单个 Agent 的行为决策与执行。
- `EventStore` 是事实层。
- `Checkpoint/Store` 是执行上下文层和记忆层。
- `Policy Gate` 是行为边界执法层。

## 3. 行为边界（硬约束，不靠提示词）

### 3.1 允许动作集合（Action Contract + 可扩展注册）

“知行合一”在本项目里的定义是：Agent 只能在允许动作集合内决策和执行，动作越界直接拒绝。  
不是“必须先有某个主引用”才算知行合一。

动作必须来自注册表（含版本），否则拒绝落地。首批建议：

- `speak`：对群发言。
- `ask_agent`：向某个 Agent 定向请求。
- `observe_only`：只观察不发言。
- `listen_only`：静默监听。
- `search_web`：联网检索。
- `request_file`：索取共享文件。
- `share_file`：发送共享文件。
- `create_group`：创建小群。
- `join_group`：加入小群。
- `assign_task`：分配任务。
- `vote_decision`：发起或参与投票决策。
- `dissolve_group`：解散小群（需权限）。
- `maintain_board`：维护任务板/记录板（增删改标记）。
- `escalate_to_boss`：请求 Boss 决策。
- `pause_self`：主动暂停。

建议注册表最小字段：

- `action_id`
- `version`
- `scope_limit`（`group:main`/`group:*`/`dm`）
- `approval_policy`（是否需 Boss）
- `citation_policy`（`none|optional|required_focus`）
- `enabled`

### 3.2 经典可扩展动作案例

建议先按“协作治理”优先扩展三类：

- 组织治理：`vote_decision`、`dissolve_group`、`transfer_group_owner`。
- 协作执行：`assign_task`、`accept_task`、`close_task`。
- 记忆治理：`maintain_board`、`pin_fact`、`unpin_fact`。

这些动作都不要求改图结构，只需扩展动作注册表和对应执行节点分支。

### 3.3 事件契约（Event Contract）

每次行为必须转成事件并持久化，最低字段：

```json

  "event_id": "e_20260310_000123",
  "session_id": "s_abc",
```

## 4. World scope 可见性设计

参考 QQ/微信式协作，固定三层 scope：

- `group:main`：主群（所有成员默认加入）。
- `group:<group_id>`：小群（任务导向分组）。
- `dm:<agent_a>:<agent_b>`：双边私聊。

设计重点：

- 可见性规则由 `route_scope` 节点执行，不放在 LLM 自由文本里。
- 事件始终写入全量事实库；可见性只影响“谁能消费”。

## 5. 边界治理节点（必须落图）

至少四个硬节点：

- `schema_validate_node`：输出结构不合法直接重试或降级。
- `action_registry_guard_node`：动作是否存在、版本是否可用。
- `policy_gate_node`：动作是否越权、是否需要 Boss 审批。
- `citation_guard_node`：按 `citation_policy` 做条件校验，不再默认强制“唯一主引用”。
- `idempotency_guard_node`：重放时避免重复副作用。
