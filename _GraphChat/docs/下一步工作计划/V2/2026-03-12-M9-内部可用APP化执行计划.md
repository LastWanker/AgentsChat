# 2026-03-12 M9 内部可用 APP 化执行计划

> 计划窗口：2026-03-13 ~ 2026-03-20  
> 计划目标：把当前 `_GraphChat` 从“Runtime + CLI/demo”推进到“内部可用 Web App（可部署、可操作、可观测）”。

## 1. 内部可用定义（本计划的验收标准）

满足以下 6 条即视为 M9 完成：

1. 能通过 HTTP API 完成核心闭环：发消息、流式回传、world command、审批处理、direct chat。
2. 有一个最小 Web 控制台，非研发人员无需命令行可跑通核心流程。
3. 有基础鉴权（单一内部 token）和基础错误处理（统一错误码 + request_id）。
4. 有最小运维能力：`/healthz`、`/readyz`、日志落盘、启动脚本。
5. 有自动化回归：新增 API/端到端测试，且现有测试不回归。
6. 有操作文档：启动、配置、常见故障、审批处理流程。

## 2. 范围与非目标

范围内（M9）：

- 单实例部署（内网）
- 单组织使用（不做租户隔离）
- 基础鉴权（token）
- SSE 流式消息
- 最小可用 UI（功能优先）

范围外（M9 不做）：

- 复杂 RBAC 与 SSO
- 多实例水平扩展
- 高可用编排（K8s/服务网格）
- 完整前端工程化重构

## 3. 当前基线（执行起点）

- Runtime 能力已具备：`submit_user_text/stream_user_text/submit_world_command/resolve_approval/direct_chat_with_agent`。
- API 目前是类封装，不是 HTTP 服务：
  - `src/graphchat/interfaces/api/app.py`
- 最小业务闭环已有脚本与集成测试：
  - `scripts/demo_m6_app.py`
  - `tests/integration/test_m6_minimal_app_flow.py`

## 4. 分阶段执行计划（可直接照单实施）

## 4.1 阶段 A：HTTP 服务骨架（2026-03-13）

目标：把 `GraphChatAPI` 包装为 FastAPI 可运行服务。

任务：

1. 新增服务入口：
   - `src/graphchat/interfaces/api/server.py`
2. 新增配置模型：
   - `src/graphchat/interfaces/api/settings.py`
3. 组装 Runtime 生命周期（startup/shutdown）：
   - 复用 `GraphChatRuntime`，不复制业务逻辑。
4. 新增基础接口：
   - `GET /healthz`
   - `GET /readyz`

验收：

- `uvicorn` 能启动，健康检查返回 200。

## 4.2 阶段 B：业务接口落地（2026-03-14 ~ 2026-03-15）

目标：把内部使用必需能力全部 HTTP 化。

任务：

1. 新增 REST 接口（复用现有 runtime 方法）：
   - `POST /v1/sessions/{session_id}/messages`
   - `POST /v1/sessions/{session_id}/world-commands`
   - `GET /v1/approvals`
   - `POST /v1/approvals/{request_id}/resolve`
   - `POST /v1/sessions/{session_id}/direct-chat`
   - `GET /v1/sessions/{session_id}/observability`
2. 新增 SSE 接口：
   - `GET /v1/sessions/{session_id}/stream?text=...`
3. 新增请求/响应 schema（Pydantic）：
   - `src/graphchat/interfaces/api/schemas.py`
4. 新增统一异常处理与 request_id 中间件。

验收：

- curl/HTTPie 能跑通“发消息 -> 收消息 -> 触发审批 -> resolve -> 继续输出”。

## 4.3 阶段 C：内部控制台 MVP（2026-03-16 ~ 2026-03-17）

目标：提供最小可用网页操作面板，脱离命令行演示。

任务：

1. 新增静态页面：
   - `src/graphchat/interfaces/ui/internal_console.html`
2. 页面能力：
   - 会话输入与消息区
   - SSE 实时输出区（node_update + message）
   - 审批待办与一键同意/拒绝
   - world command 输入区
   - direct chat 输入区
   - observability 快照查看（含 `plan_execution_report`）
3. 服务端挂载静态资源路由（FastAPI）。

验收：

- 内部用户只通过浏览器完成一轮完整流程，无需终端命令。

## 4.4 阶段 D：运维最小闭环（2026-03-18）

目标：可稳定运行，可定位问题。

任务：

1. 新增运行脚本：
   - `scripts/run_api_server.py`
   - `scripts/run_internal_console.py`（可选，若与 API 同端口可省）
2. 环境变量规范化：
   - `GRAPHCHAT_API_TOKEN`
   - `GRAPHCHAT_DATA_DIR`
   - `GRAPHCHAT_LOG_LEVEL`
   - `GRAPHCHAT_HOST`
   - `GRAPHCHAT_PORT`
3. 新增日志规范：
   - 请求日志（request_id/session_id/path/status/duration）
   - 错误日志（异常堆栈 + request_id）

验收：

- 重启后数据可读，错误可根据 request_id 追踪。

## 7. 风险与回退策略

风险 1：SSE 在内网代理环境不稳定。  
回退：保留短轮询接口 `GET /v1/sessions/{session_id}/events`，SSE 失败时自动降级。

风险 2：审批链路与 HTTP 接口线程模型冲突。  
回退：审批先走串行处理（单 worker），确认稳定后再放开并发。

风险 3：UI 增加后排障复杂。  
回退：始终保留 CLI 与 `demo_m6_app.py` 作为基准通路。
