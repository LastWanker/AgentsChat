## 1. 背景与目标
- 背景：你提出要去掉 agent 主图里显式写死的 `retrieval/board/governance` 顺序，把它们都收敛到计划驱动的并行任务流中。
- 目标：把 `action_parallel_subgraph` 升级为 Planner-Executor，计划语言控制顺序与并行，执行阶段按每个 skill 的 guard profile 运行。

## 2. 设计结论（先回答你的关键问题）
- `action_parallel_subgraph` 不是“纯编排”，而是“编排 + 执行”一体。
- 执行发生在 `execute_step` 节点：每个 step 会真正调用 skill 与其 guard，再返回 `action_results/emitted_events`。
- “是否执行完成”不是看主图边，而是看 `plan_execution_report.completed`：
  - `True`：计划内 step 均执行完（`remaining_steps` 为空）。
  - `False`：TTL 或依赖问题导致有剩余 step。

## 3. 代码落地点
1. Agent 主图收口（主图不再显式表达 action 顺序）
   - `src/graphchat/application/graphs/agent_graph.py`

2. 执行与汇总在 `action_parallel_subgraph`

   - `select_ready_steps + Send` 做波次并行调度。
   - `execute_step` 调用 `_execute_action_step`，其中会按 profile 执行：

   - `finalize_plan` 输出 `plan_execution_report`。
3. 每个 skill 的 guard profile 配置化
   - `src/graphchat/application/skills/guard_profiles.py`
   - `src/graphchat/application/runtime.py`
   - `src/graphchat/interfaces/api/app.py`
   - 支持默认 profile + override + runtime patch（`set_skill_guard_profile`）。
4. 状态与可观测
