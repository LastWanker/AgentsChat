# 2026-03-12 M8 执行子图显式化记录

## 1. 你提出的问题
- 现状里 `action_parallel_subgraph` 同时承担编排与执行，虽然逻辑正确，但状态机层面“执行阶段”不够显式。
- 你希望在 `action_parallel_subgraph` 与 TTL 生命周期节点之间，存在一个独立执行子图节点，并且子图里能看到离散 skill 节点。

## 2. 设计决策
1. 保留 Planner-Executor 思路，但把“编排”和“执行”拆成两个显式节点：
   - `action_parallel_subgraph`：仅负责计划规范化与执行前准备（plan only）
   - `skill_execution_subgraph`：负责真正 skill 执行与 guard 链应用
2. 执行子图内部采用“离散 skill lane + 并行分发”：
   - 不做固定串行链
   - 通过 `Send` 把 ready step 分发到 skill lane 节点
3. 完成判定继续使用 `plan_execution_report.completed`：
   - 这比只看主图边更准确，能反映 TTL 中断、依赖未满足等情况

## 3. 目标状态机
- Agent 主图：
  - `listening_subgraph -> decide_wake -> plan_action -> action_parallel_subgraph -> skill_execution_subgraph -> lifecycle_gate`
- 执行子图（skill_execution_subgraph）：
  - `select_ready_steps`
  - `skill_rag`
  - `skill_board`
  - `skill_governance`
  - `skill_dialog`
  - `skill_generic`
  - `merge_wave`
  - `finalize_plan`

说明：
- `skill_*` 节点不是顺序链，而是分流并行的执行落点。
- guard profile 仍按每个 action 生效，不回退到全局固定 guard 串。

## 4. 验收口径
- 图层面：AgentGraph 中必须出现独立 `skill_execution_subgraph` 节点，位置在 `action_parallel_subgraph` 与 `lifecycle_gate` 之间。
- 行为层面：真实 action 执行发生在 `skill_execution_subgraph` 的 `skill_*` 节点中。
- 结果层面：`plan_execution_report` 必须给出 `completed/remaining_steps`，作为执行完成判定。
