## M7 Planner-Executor 收口与 Skill Guard 配置化（已完成）
### 目标
- 让 `agent` 主图不再显式串行 `retrieval/board/governance/guard` 节点，统一收敛到 `action_parallel_subgraph`。
- 把“行为执行顺序”交给计划语言（`actions[]` + `depends_on` + `dispatch` + `priority`），而非主图写死顺序。
- 把 guard 从“全局固定串”改为“每个 skill 绑定 profile”，支持运行时配置和观察。

### 已落地
1. `agent` 主图收敛为 `listening -> decide_wake -> plan_action -> action_parallel_subgraph -> lifecycle_gate`：
   - `action_parallel_subgraph` 内部同时负责“计划波次编排 + skill 执行 + guard 链应用 + 结果汇总”。
2. 计划执行报告：
   - 新增 `plan_execution_report`，包含 `total_steps/executed_steps/remaining_steps/completed/ttl_after_execution`，明确计划是否执行完毕。
3. guard profile 配置化：
   - 新增 `src/graphchat/application/skills/guard_profiles.py`。
   - `runtime` 初始化默认 profile，并支持 `set_skill_guard_profile(action_id, **patch)` 运行时调整。
   - observability 输出 `skill_guard_profiles` 快照，便于验收配置是否生效。
4. “每个 action 绑定 guard”在执行层已落地：
   - `action_parallel_subgraph` 在 `execute_step` 中按 step 的 action 解析 profile，再按 profile 决定是否执行 citation/policy/schema/registry/idempotency guard。
   - `retrieval/board/governance` 也按 profile 进入每个 step 的执行路径，而不是主图显式节点串联。

### 验收
- 单元测试通过：
  - `tests/unit/test_action_parallel_subgraph.py`
  - `tests/unit/test_skill_guard_profiles.py`

## M8 执行子图显式化（已完成）
### 目标
- 在 `action_parallel_subgraph` 与 `lifecycle_gate(TTL)` 之间增加显式执行子图节点，表达“先编排、后执行”的状态机顺序。
- 执行子图内显式存在 skill 节点（并行分发、非串行链式），使 skill 执行成为主状态机可观察的一部分。

### 已落地
1. Agent 主图链路升级为：
   - `plan_action -> action_parallel_subgraph(plan only) -> skill_execution_subgraph -> lifecycle_gate`
2. `action_parallel_subgraph` 切换支持 `plan_only` 模式：
   - 仅规范化 `actions[]` 到 `plan_steps`，不做 skill 执行。
3. 新增 `skill_execution_subgraph`：
   - 由 `select_ready_steps + Send` 分发到多个 skill lane 节点（`skill_rag/skill_board/skill_governance/skill_dialog/skill_generic`）。
   - 各 lane 并行执行后汇聚 `merge_wave -> finalize_plan`，产出 `action_results/emitted_events/plan_execution_report`。
4. 与 M7 的 guard profile 机制保持一致：
   - 每个 step 在执行时按 action 对应 profile 决定 guard 链与子图调用，行为不再由主图写死顺序。

### 验收
- 执行顺序显式可见：
  - agent 图存在独立 `skill_execution_subgraph` 节点，且位于 `action_parallel_subgraph` 与 `lifecycle_gate` 之间。
- 单元与集成回归通过（见下方全量结果）。
