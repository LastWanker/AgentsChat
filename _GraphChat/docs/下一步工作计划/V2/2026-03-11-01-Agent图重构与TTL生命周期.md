# 01 Agent图重构与 TTL 生命周期（执行细案）

## 1. 改造目标

1. 从“单动作 `planned_action`”升级为“多动作 `actions[]` 计划”。  
2. `citation_guard` 之后进入并行行动子图（speak/board/governance 可并行、可跳过）。  
3. `listening` 与 `silent_loop_subgraph` 形成循环对。  
4. 引入 TTL 生命周期：`working/idle/sleeping/lastlife`，并定义消耗规则与一次续费机制。  
5. guard 邻居节点收敛为 `guardrail_subgraph`。

## 5. Listening/Silent 循环细化

## 5.1 listening 节点职责扩展

文件：`src/graphchat/application/nodes/agent_nodes.py`

- 读取：
  - `visible_events` 最近窗口
  - `board_snapshot` 摘要（通过 BoardStore 查询，避免全量拼 prompt）
- 输出：
  - `last_event`
  - `board_snapshot_digest`
  - `trace`

## 5.2 silent loop 消耗规则

文件：`src/graphchat/application/graphs/subgraphs/silent_loop_subgraph.py`

- 每次静默轮询消耗 TTL：`global_ttl -= 1`
- 唤醒条件：
  - 被 @
  - phase override
  - 有待办事务（board 或任务上下文命中）
  - 或达到静默轮次阈值（阈值应大于 TTL 的安全参数）

说明：`max_silent_rounds` 在生产配置中设置为“大于 TTL 的安全值”，避免它主导唤醒。
当前约定：`ttl_initial=15`，测试阶段可保守配置；稳定后再上调。

## 6. TTL / lastlife / 一次续费

新增节点建议（`application/nodes/agent_nodes.py`）：

- `ttl_tick_node`：循环发生时统一扣 TTL
- `ttl_renew_decision_node`：TTL 归零时判断是否续费一次
- `lastlife_notice_node`：进入 lastlife 时向模型注入“最后一次收敛工作”的强提示

规则：

1. 以下都算“循环消耗”：
   - listening<->silent 轮回
   - guard 打回
   - 自激活继续工作
2. TTL 耗尽：
   - 若 `ttl_renewed=False` 且判定继续一次工作：续费（固定额度），置 `ttl_renewed=True`，进入 `lastlife`
   - 否则进入 `sleeping`
3. `lastlife` 只允许一次，结束后必须睡眠并等待世界/Boss 唤醒。
4. `lastlife_threshold` 暂定 `3`：当 TTL 低于等于阈值时，提示词必须引导代理尽快收敛任务。

## 7. 并行动作子图（核心）

新增文件：`src/graphchat/application/graphs/subgraphs/action_parallel_subgraph.py`

子图结构：

- `normalize_actions`：按 priority 排序，过滤非法 action
- `normalize_actions`：按 `step_index`（优先）或 `priority`（兜底）排序，过滤非法 action
- `dispatch_actions`：对 `selected_actions` 产出 `Send(...)`
- 执行节点（并行）：
  - `do_speak`
  - `do_board`
  - `do_governance`
  - `do_misc`
- `collect_action_results`：汇总并生成标准事件草案

关键点：

- governance 是并行分支之一，不是必经串联链路。
- `can_skip=true` 且条件不足时直接 skip，不影响其他分支。
- 输出统一进入 guardrail 子图，最后 emit。
- 默认优先级：`board > speak > governance`，但以 LLM 显式计划顺序覆盖。

## 8. Guardrail 子图抽象

新增文件：`src/graphchat/application/graphs/subgraphs/guardrail_subgraph.py`

包含节点：

- `policy_gate`
- `schema_guard`
- `action_registry_guard`
- `idempotency_guard`

理由：

- 你提出“相邻 guard 合并抽象”与当前拓扑高度一致。
- 该子图可作为统一安全闸，供未来多行动分支共用。
